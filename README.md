# 野人量化 · yeren-tide

> 潮水退去，才知道谁在裸泳。这个工具做的事，是把「潮水退到了哪一层」算出来。

把《全能野人交易方法完整总结》里的交易体系，做成一个能算、能看、能装进手机的量化工具。
纯前端实现（无后端、无框架依赖），数据走公开行情接口，最终打包成 Android APK。

**名字的来历**：`yeren` 是这套方法的名字——不预测、不解释、只跟随；`tide` 是它真正研究的东西，
情绪潮汐。涨停梯队是浪高，两市量能是潮位，退潮期的仓位上限就是水退到哪一步。
整个工具只回答一个问题：**现在的水位，能不能下水。**

## 二、应用内更新

更新这件事在国内有两个坑：GitHub 时通时不通，WebView 又不能把文件落盘。
所以拆成两段解决——**清单走 CDN，安装包走原生**。

**清单**放仓库里的 `dist/update.js`（内容是 `window.YB_UPDATE = {...}`）。
为什么不用 `fetch` 拿 JSON：页面是 `file://`，跨域到 https 会被拦；而 `<script>`
标签不受 CORS 限制——这和整个项目拉行情用的是同一套思路。

**六个源并行竞速**，谁先回用谁：

```
jsDelivr (cdn / fastly / gcore)   ← 国内有节点，通常最快
ghfast / ghproxy                  ← 公益反代，偶发抽风但兜得住
raw.githubusercontent.com          ← 直连，国内多数时候不通，最后兜底
```

不用「逐个重试」是因为每个源超时 7 秒，串行 6 个最坏要 40 秒；并行最坏也是 7 秒。

**下载交给原生**（`Updater.java`）：`HttpURLConnection` 没有 CORS，镜像和 Release 直链都能用，
逐源尝试，下到 `.part` 再改名（半包如果直接叫 `.apk`，下次会被误判成已下载）。
装好前会检查「安装未知应用」权限，没开就带去设置页，回来再点一次即可——
同版本的包会复用缓存，不重复下载。

**一个绕不开的坑**：jsDelivr 只代理前端资源，`.apk` 会被 301 回 `raw.githubusercontent.com`，
而 raw 在国内基本不通。所以单独存一份 `dist/cdn/yeren-quant-<版本>.apk.js`，
把二进制改成 `.js` 后缀——它才当普通资源代理。文件名带版本号是为了绕开
jsDelivr 对固定路径的 12 小时缓存。

实测各源「国内直连、不走代理」的结果（2026-11-21）：

| 源 | 结果 |
|---|---|
| `ghproxy.net` | ✓ 200，清单与安装包都可用 |
| `fastly.jsdelivr.net` | ✓ 200，清单与 `.apk.js` 副本可用，约 78 KB/s |
| `gcore.jsdelivr.net` | ✓ 200 |
| `cdn.jsdelivr.net` | ✗ 不通 |
| `ghfast.top` | ✗ 不通 |
| `raw.githubusercontent.com` | ✗ 不通（直连预期内） |

没有一个源能覆盖所有人，所以只能全打一遍。清单还要「取版本号最大的那份」而不是
先到先得——jsDelivr 缓存旧清单时会返回上一个版本，先到先得会让用户被告知「已是最新」。

## 四、量化模型

模型严格按文档的四层结构落地，源码在 `www/js/engine.js`，每条规则都标了章节号。

### L1 情绪周期（第三章）

七个分项各自归一化到 `[0,1]` 后加权求和，满分 100：

| 分项 | 权重 | 归一化区间 | 对应文档指标 |
|---|---|---|---|
| 涨停强度 | 0.16 | 12 → 80 家 | ① 涨跌家数 |
| 跌停反向 | 0.16 | 0 → 22 家（反向） | ① 赚钱效应 |
| 封板率 | 0.12 | 55% → 88% | ② 晋级率 / ③ 炸板修复 |
| 连板高度 | 0.10 | 1 → 8 板 | 题材延续性 |
| 量能环比 | 0.14 | 0.80 → 1.25 倍 | ① 成交量 |
| 涨跌比 | 0.14 | 30% → 70% 上涨占比 | ① 普涨程度 |
| 昨停溢价 | 0.18 | -3% → +5% | ② 做多资金还在不在 |

**阶段判定**不是纯看分数，还看结构（文档 3.3 对「冰点」的定义是双杀 + 核心股跌停）：

```
跌停≥12 且 涨停≤25 且 分数<40  → 冰点期   仓位 0%
分数 < 30                      → 冰点修复  仓位 10%
分数 < 46                      → 试错期    仓位 20%
分数 ≥ 74                      → 高潮期    仓位 30%
分数 ≥ 50 且 涨跌比≥0.5 且 溢价>0 → 主升期  仓位 50%
其余                           → 试错期(结构不足)
```

主升期额外要求「普涨 + 昨日涨停还能溢价」，因为文档对主升的定义是「龙头回封、小弟批量助攻、中军启动」——光有分数、结构不支撑时，仍然按试错期对待。

**退潮预警**用四个结构特征投票（命中 2 项即预警、3 项直接压到 10% 仓位）：
涨停多但封不住 / 跌停抬头 / 高度被压制 / 昨停今日亏钱。

### 两市量能：四维模型（文档 4.4）

早期只用「今日 ÷ 近 5 日均量」，结论永远在「放量/缩量/平量」之间打转。
复盘 2026-05 至 11 的真实数据后发现问题很大：

| 月份 | 日均量（亿手） | 上证 |
|---|---|---|
| 05 | 14.6 | 4178 |
| 06 | 14.2 | — |
| 07 | 13.0 | — |
| 08 | 11.7 | — |
| 09 | 10.7 | — |
| 10 | 10.0 | — |
| 11 | 10.5 | 3534 |

**半年缩量 31%，指数跌 15.4%，60 日均量连续 6 个月台阶式下移。**
这是缩量阴跌——没有恐慌盘，也没有增量资金。而「今日比上周多 10%」在这种背景下毫无意义。

所以拆成四个维度：

**1）水位（绝对量）**：两市成交额，1.5 万亿是能否支撑趋势的分水岭。

**2）中枢（半年台阶）**：`60 日均量 ÷ 20 日前的 60 日均量`。
连续下跌时会被 5 日环比掩盖，必须拉长才能看出。`≤-3%` 判中枢下移。

**3）位置（长周期分位）**：今日量在近 20/60/120 日中的百分位。
「量比 1.1」和「半年地量」可以是同一天，分位才说得清。

**4）性质（量价配合）**：用 `20 日均量 ÷ 120 日均量` 定中期量能方向，
配 `20 日涨幅` 定价格方向，构成四象限：

| 组合 | 性质 | 含义 |
|---|---|---|
| 缩量 + 跌 | 缩量下跌 | 阴跌无承接，等放量或地量见底 |
| 缩量 + 涨 | 缩量上涨 | 无量反弹，涨到压力位容易夭折 |
| 放量 + 跌 | 放量下跌 | 有资金出逃，等止跌信号（放量后第一根缩量阳线）|
| 放量 + 涨 | 放量上涨 | 唯一能做趋势的组合 |

为什么量能方向用 `d20/d120` 而不是 `d20/d60`：两个短窗口都包含下跌段，比值会互相抵消。
实测 `d20/d60 = 0.99`（看似平量），而 `d20/d120 = 0.87`（实际缩量 13%）。

**界面**：量能卡给出月度均量柱状图——台阶下移一眼可见，这是复盘最有价值的部分。
结论用一句话讲完：中枢方向 + 分位 + 量价性质 + 距支撑线差额。

个股页同理：`今日量 ÷ 20 日均`、`÷ 60 日均`、`近 120 日分位`，而不是只给量比。

### 高度天花板（2026-11-19 复盘补入）

原有的「连板高度」只是一个加分项，方向是错的——它把"高度越高越好"写进了模型，
却漏掉了更关键的一条：**高度本身就是短线空间的物理上限**。

复盘原话：

> 若老龙头无法打开上涨高度，下方接力资金会直接退潮，短线高度最多到 3 板，
> 3 板以上就没有性价比，资金会停止参与。
> 市场高度被压制在 2-3 板时，短线基本没有参与价值，此时只能聚焦龙头。

模型里补了三处：

**1）天花板判定**：`heightCap = max(今日最高板, 近 5 日最高板峰值)`

| 天花板 | 判定 | 仓位处理 |
|---|---|---|
| ≤ 2 板 | 极度压制 | 上限 10%，不给试错仓 |
| = 3 板 | 高度压制 | 上限 20%，首仓 ≤ 10% |
| 4-5 板 | 空间尚可 | 不额外压制 |
| ≥ 6 板 | 空间打开 | 不额外压制 |

取近 5 日峰值是为了避免单日断板把天花板看低——资金记忆还在。

**2）接力性价比**：每只涨停股算 `headroom = 天花板 − 连板数`

- `headroom < 0` 或「天花板 ≤3 且已 4 板」→ **无性价比，直接否决**（资金不会接力）
- `headroom = 0` → 已在天花板，标注「需破局才可参与」
- `headroom = 1` → 标注「性价比下降」

**3）绝对龙头识别**：`龙头度 = 身位 40 + 封单 25 + 人气 20 + 板块地位 15`

- 身位：`连板数 / 天花板`，天花板之内越高越强
- 封单：`封单额 / 流通市值`，代表抢筹强度
- 人气：成交额在全池的占比，代表辨识度
- 地位：板块内是否第一

刻意**不用综合评分**来选龙头。弱势抱团时，"绝对龙头"常常不是评分最高的那只——
评分奖励均衡，而龙头看的是极端项（封单最猛、人气最旺）。

高度压制时，除龙头外全部降级为「只观察」，并在选股页顶部给出明确结论。

**4）龙头不等于连板最高**（2026-11-19 再修正）

最初的龙头度把「身位」给到 40 分、「封单/流通市值」给到 25 分，结果是
小盘连板股永远压过真正的人气票。而且「封单/流通市值」本质衡量的是
「盘子小容易封」，对大盘股系统性不公。

实盘对照：九阳股份 1 板，成交额 51.29 亿、换手 23.7%；
当天 3 板的真视通成交额只有 0.61 亿。前者是资金焦点，后者只是身位高。

现在的口径：

- **候选池扩大到「涨停股 + 当日强势股」**（涨幅≥5%、成交额≥2亿、流通 20-800亿），
  龙头不必涨停
- **权重改为人气主导**：人气 35（成交额，sqrt 压缩）+ 强度 25（涨幅）+ 活跃 15（换手）
  + 身位 15（连板/天花板）+ 板块 10（板块内成交额第一）
- **龙头豁免池内否决**：文档 6.1-3 把「烂板 → 次日弱转强 → 再度回封」列为买点，
  所以炸板 13 次的九阳仍是龙头，只是把风险标出来
- **炸板惩罚改为封顶 + 换手折扣**：13 次 ×4 = -52 分会把分数砸成 0，
  改为封顶 20 分，换手 ≥15% 时再打五折

**5）普涨但无高度的识别**：`涨跌比 ≥ 60% 且 天花板 ≤ 3`

这是 11-19 那种"连续 6 天 4500 家上涨、但短线极难做"的盘面。模型会显式提示
"涨停家数多不代表短线好做，资金分散在低位轮动"，避免被普涨的高涨跌比骗出高仓位。


### L2 量能（第四章）

- **量能环比**：今日两市成交量 ÷ 近 5 日均量。
  盘中不能直接比——早上 9:50 只成交了全天的一小部分。所以按 A 股日内成交量的 U 型分布做锚点插值，把盘中量还原成全天口径再比。
- 其余量能判断（缩量回踩、放量滞涨、红肥绿瘦）都落在选股与买点层。

### L3-A 短线情绪池（第五章 5.1）

对每个涨停股打分，满分 100：

```
板块地位 30  ← 板块内连板最高者=龙一；大市值+高辨识度=中军；其余=跟风
连板高度 22  ← 5板+ 22 / 4板 20 / 3板 17 / 2板 12 / 首板 5
封单强度 16  ← 封单额 ÷ 流通市值（≥6% 满分）
市值适配 14  ← 50-300亿最佳；<20亿判杂毛
换手健康 10  ← 3%-20% 最佳；>30% 扣分
封板时间  8  ← 越早封板越强
扣分      ← 炸板次数 ×4
```

**硬否决**（评分封顶 35、仓位强制归零）：ST、北交所、流通市值 < 20 亿、连板≥6 且换手>35%、炸板≥3 次。

**黑名单提示**按文档第十章逐条落地：首板非爆发日、一进二、二进三、高位区、孤军、跟风。

### L3-B 波段资金池（第五章 5.2 / 4.10）

月线资金流法，判定链：

```
月线：连续 4-5 个月「放量 + 红柱」，且 6 个月涨幅 ≤50%、250 日涨幅 ≤100%（翻倍不看）
周线：MA5 > MA10 且 5 周均线向上 且 站上 20 周线
日线：20 日线拐头向上、近 20 日内有涨停、缩量到 5 日均量 75% 以下、收阴线
买点：以上同时成立 → 「买点成立」
```

两个实现上的坑（都有回归测试兜着）：
1. **当月是不完整月份**，总成交量只有零头。若直接比月总量，「连续放量」永远判不出来 —— 所以用「月均日成交量」比较。
2. **250 日分位跟「周线上升」自相矛盾**（连涨 5 个月的票分位必然接近 1）。所以「不在高位」改用「6 个月涨幅≤50% 且离 60 日线不超 35%」。

### L3-C 买点识别（第六章，可判定子集）

| 已实现 | 判定条件 |
|---|---|
| 分歧转一致 | 前日量 > 5日均量×1.6，今日量 < 前日×0.55，且价格新高 |
| 低位放量涨停 | 涨停 + 量 > 5日均量×2 + 250 日分位 < 0.6 |
| 缩量回踩阴线 | 量 < 5日均量×0.7 + 收阴 + 未破 20 日线 + 20 日内有涨停 |
| 龙头首阴 | 20 日涨幅 > 40% + 首根放量阴线（只做隔日） |
| 高位放量滞涨 | 近 60 日高位 + 量 > 5日均量×1.8 + 涨幅 < 2.5%（卖出信号） |
| 跌破 20 日线 | 卖出信号 |

### L4 风控（第七、八章）

```
仓位上限 = min(情绪阶段上限, 单笔风险预算 ÷ 止损幅度) × 评分修正
单笔风险预算 = 总资金 × 2%
止损幅度 = 6%（可调 1%-20%）
评分修正：A 1.0 / B 0.8 / C 0.5 / D 0.25
首仓 = min(10%, 建议仓位)
```

配套：各阶段仓位刻度表、每日执行清单（可勾选、本地持久化）、黑名单九条、止损/保本/目标价计算。

### L5 持仓（第八、九章的落地）

持仓不是简单的记账本，它跟风控是联动的——每次刷新都会拿当前持仓去对一遍纪律：

| 检查项 | 触发条件 | 出处 |
|---|---|---|
| 已破止损 | 现价 ≤ 成本 ×(1-止损幅度) | 第七章「触发即砍，不眨眼」 |
| 逼近止损 | 现价 ≤ 成本 ×(1-止损×0.6) | 同上，提前给预案 |
| 总仓超限 | 总仓位 > 当前情绪阶段上限 | 第八章「未稳定前用固定仓位」 |
| 单只超重 | 单只仓位 > 阶段上限 | 等于把试错仓一次打满 |
| 持仓过散 | 只数 > 5 | 他自述常态 4 只左右 |
| 黑名单 | ST / 北交所 | 第十章 |

工程上参考了 GitHub 上 portfolio tracker 的常见做法：

- **纯本地持久化**（localStorage），不做后端，不上传任何数据
- **加权平均成本**：同一标的多次买入自动合并，不会出现两行
- **未实现 / 已实现分离**：清仓后进「交割单」，单独统计已实现盈亏与胜率
- **仓位占比的分母是总资金**，不是持仓市值——因为他的仓位上限一直是按总资金算的
- 派生指标全是 `现价 × 数量` 的纯函数，行情刷新即可重算，不存冗余字段

## 五、数据源架构

东方财富的限流是这套东西最大的工程约束。实测 `push2` 连发 3 次就有 2 次直接拒连，所以做了分工：

| 用途 | 主源 | 兜底 | 说明 |
|---|---|---|---|
| 个股/指数行情 | 腾讯 `qt.gtimg.cn` | 新浪 `hq.sinajs.cn` | 腾讯无限流，一次可批量 50 只 |
| 日 K 线 | 腾讯 `proxy.finance.qq.com` | 腾讯 `web.ifzq.gtimg.cn` → 东财 `push2his` | 见下方说明 |
| 涨停池 / 跌停池 / 炸板池 | 东财 `push2ex` | — | 无替代品，但接口轻 |
| 涨跌家数 | 东财 `getTopicZDFenBu` | — | 一次请求拿到全市场涨跌分布 |
| 全市场榜单（波段初筛） | 东财 `clist` | 涨停池+炸板池 | 失败时自动降级 |

### 绕开 CORS

所有行情接口都不返回 CORS 头，浏览器 `fetch` 会被拦。所以**一个 fetch 都没用**，全部走 `<script>` 注入：

- 腾讯/新浪：接口直接给全局变量赋值（`v_sh600000="..."`），插脚本后读变量
- 东财：支持 `cb=` 回调，走 JSONP
- 腾讯 K 线：支持 `_var=`，同理

同时声明 `script.charset = 'gbk'`，否则腾讯、新浪返回的 GBK 中文会乱码。

### 限流对策（四层）

1. **串行闸门**：所有东财请求排队，最小间隔 380ms。这是最有效的一层。
2. **分级缓存**：今日涨停池 60s、昨日涨停池 10min（名单是静态的）、涨跌分布 60s、K 线 60s。
3. **退避重试**：350ms → 900ms → 1800ms。
4. **降级**：东财挂了就用上一份数据（界面上明确提示），不把表格刷成空白。

### K 线为什么换了主源

实测 `web.ifzq.gtimg.cn` 在频繁请求后会返回一个 JS 反爬挑战页，`script.onerror` 直接触发。而 `proxy.finance.qq.com/ifzqgtimg/...` 是同一套 `fqkline` 接口、同样的返回格式，但没有这个风控。所以主源改走 proxy，`web.ifzq` 退为第二顺位，东财 `push2his` 第三。

## 七、加载性能

首屏从 **4.5 秒降到 0.7~1 秒**（热启动 6ms）。实测各环节耗时：

| 环节 | 耗时 |
|---|---|
| 腾讯指数 | 0.5s |
| 东财四个池 | 0.6s（并发 3） |
| 昨日池的今日报价 | 0.5s |
| 量能趋势 K 线 | 1.5s |
| 强势股榜（常被限流） | 2.5s 才失败 |

早期这些是**串成一条链**的，相加就是 4.5 秒。改了三处：

**1）东财队列从「完全串行」改成「错峰并发」**

原来 380ms 一个，5 个请求排队 1.9 秒，光排队就吃掉一半首屏。
实测东财能承受 3 个并发（真正触发限流的是密集连发，不是并发本身），
改成同时 3 个在飞 + 每次发起间隔 150ms，5 个请求从 1.9s 降到 0.7s。

带自适应降速：连续失败 2 次自动退回单并发 + 400ms，成功即恢复。

**2）把「不该阻塞首屏」的东西移出去**

- 强势股榜只影响龙头识别 → 后台拉，用上次缓存兜底，回来后只在龙头真的变了才重绘
- 昨日涨停池是静态名单 → 落 localStorage，隔天打开秒读

**3）日线走磁盘缓存（stale-while-revalidate）**

K 线 1.5 秒，但它只用来算量能趋势，而且日线绝大部分是历史数据、永远不会变。
现在日/周/月线都落本地（保留 90 根），有缓存就立即返回、同时后台静默刷新。

**4）界面快照秒开**

每次成功加载后把市场页精简存到本地。下次打开先把快照铺上去（页脚标注
「本地缓存，正在刷新…」），再静默刷新。超过 12 小时的快照不铺，避免展示过期盘面。

实测：冷启动首屏 693~978ms，热启动 **6ms**。

**5）其它交互优化**

- 各页面记住滚动位置：从市场页滚到板块榜、点进二级页、再返回，落点还在原处
- 切换 tab 不会把已经滚下去的列表弹回顶部

### 板块二级页（个股审美排名）

板块榜每行可点，进入二级页看该板块内个股排名。**不是按综合评分排，而是按审美**：
同一板块里，资金最先想到谁，谁就是龙头。

| 维度 | 权重 | 含义 |
|---|---|---|
| 身位 | 30 | 连板数 / 板块内最高板 |
| 人气 | 25 | 成交额，sqrt 压缩 |
| 封单 | 20 | 封单额 / 流通市值 |
| 时间 | 15 | 首封时间（9:30 前 15 分，收盘前 3 分） |
| 换手 | 10 | 换手率 20% 封顶 |

五项都在**板块内**做相对比较，避免跨板块失真。输出 S/A/B/C 四档。

板块成员 = 涨停股 + 当日强势但未涨停的同板块个股（后者的身位、封单为 0，
自然排在后面，但人气项仍能得分）。这样板块的强弱不会被「只有几只涨停」低估。

### 个股详情页：三张主图，默认分时

主图区右侧是竖排切换按钮（**分时 / 日K / 筹码**），默认分时——
这是看个股的第一直觉：今天走得怎么样。

```
页头      名称 / 代码
行情条    现价 涨跌幅 / 开高低额 / 换手 量比 流通盘 PE
决策卡    结论 + 最关键的一条理由（其余折叠）
          ├ 止损（技术位优先）/ 目标 / 建议仓位
主图区    分时 · 日K · 筹码      ← 右侧竖排切换
统计行    分时：均价/最高/最低/偏离均价/全程成交
          筹码：平均成本/获利比例/90%成本区间/集中度
位置卡    主力成本 / 偏离成本 / 分位 / 量能长周期 / RS / 板块排名 / 压力支撑
涨停基因  次数 / 次日均值 / 溢价率 / 连板率
```

**分时图**用「左价格、右涨跌幅」双轴——两者都塞右侧时 46px 放不下两列数字，会直接重叠。
昨收基准线单独画虚线（不能指望网格正好落在昨收上），成交量柱按「相对上一分钟」着色，
而不是相对均价（否则一天大部分时间在均价下方，柱子全是绿的）。

**筹码分布**的通达信算法：每日成交按价格区间三角形铺开，历史筹码按换手率逐日衰减。

关键是换手率必须用**真实值** `成交量 ÷ 流通股本`（流通股本 = 流通市值 ÷ 现价）。
早期用「相对 20 日均量 × 3%」估算，九阳实际日换手 20% 被估成 3%，
结果半年前 8 元的筹码衰减不掉，平均成本算成 21.26、集中度 53.7%，全都是错的。
改用真实股本后：平均成本 27.67、获利 52%、集中度 18.1%、筹码峰 29.37，与走势吻合。

取景范围用 90% 成本区间，而不是全部历史价格——否则几个月前的零星低价筹码
会把价格轴从 21-31 拉到 6-35，真正密集的区间压成一条线。

**三层信息各回答一个问题**：分时答「今天怎么样」，日K答「趋势和位置」，筹码答「上方谁在套、下方谁在赚」。

### 个股详情页（决策优先，不是图表放大）

个股页的设计原则：**先给结论，再给证据**。打开页面第一眼看到的不是 K 线，
而是「这只票能不能买、亏在哪、买多少」。

```
页头      名称 / 代码
行情条    现价 涨跌幅 / 开高低额 / 换手 量比 流通盘 PE
决策卡    结论（可参与·只做回封·观察·回避）+ 最关键的一条理由
          ├ 止损（技术位优先，不是死板的 6%）
          ├ 目标（下一板 / 波段位）
          └ 建议仓位 + 首仓
周期      日K / 周K / 月K
十字光标  日期 开高低收 / MA5·10·20·60 / 成交量
K 线图    蜡烛 + 均线 + 成交量，默认放大视野
位置卡    主力成本 / 偏离成本 / 60·250 日分位 / 量能 / 相对强弱 / 板块排名 / 压力支撑
涨停基因  涨停次数 / 次日均值 / 次日溢价率 / 连板率 / 最近涨停 / 阈值
```

**为什么这么排**：决策卡默认只显示一条最关键的理由，其余折叠——如果把所有
理由都铺开，卡片会把 K 线顶出首屏，那就成了「更大」而不是「更深入」。

**三个通用行情软件不会给你的指标**：

1. **主力成本（60 日 VWAP）与偏离度** —— 现价比主力成本高 33% 意味着获利盘厚重，
   任何回调都会被抛压放大。这比「涨了多少」更能说明风险。

2. **涨停基因** —— 同一板块里，有的票涨停后次日平均 +3%，有的 -2%。
   这个差异比任何技术形态都重要，却要自己拿历史数据算。现在直接给出：
   近 250 个交易日的涨停次数、次日涨幅均值、溢价率、连板率。
   判定：`次日均值 ≥2% 且 溢价率 ≥60%` → 接力成功率高；`均值 <0 或 溢价率 <45%` → 不值得接力。

3. **相对强弱 RS** —— 近 20 日个股涨幅 ÷ 指数同期涨幅。RS < 0.95 说明不是资金主攻方向，
   形态再好也只是跟风。

**决策逻辑的优先级**（这部分是踩过坑才理清的）：

| 顺序 | 判据 | 结论 |
|---|---|---|
| 1 | 涨停池已否决（ST / 市值 / 换手） | 回避 |
| 2 | 超出高度天花板 | 回避 |
| 3 | 均线空头排列 | 回避（同时提示当日是否放量下跌）|
| 4 | 当日放量大跌 ≥5% | 回避（出货不是洗盘）|
| 5 | 当日缩量大跌 ≥5% | 不接（没人接，反弹不追）|
| 6 | 偏离 20 日线 >15% | 等回踩 |
| 7 | 偏离 8~15% | 偏离偏大 |
| 8 | 贴近 20 日线且不在高位 | 可观察买点 |
| 9 | 跌破 20 日线 2~6% | 等企稳 |

早期版本把「均线空头排列」放在「放量大跌」之前，导致更紧迫的当日信号被吞掉。
现在两条都会说。

**止损不是固定百分比**：若最近的支撑位（MA10 / 前低 / MA20）比固定 6% 更近，
就用支撑位下方 1% 作为止损，并在卡片上写明依据（「跌破支撑 28.12」）。
这样止损更贴合真实结构，也省下无谓的风险敞口。

### K 线页

从涨停梯队、板块页、短线池、波段池、持仓都能点进个股详情：

- 日 K / 周 K / 月 K 三种周期，独立请求、本地缓存
- 主图：蜡烛（阳线空心、阴线实心）+ MA5/10/20/60，副图：成交量 + 量均线
- **手势按方向分流**：横向拖动看图（出十字光标），纵向拖动正常滚页面。
  这条是踩坑后的修正——早期 canvas 用 `touch-action: none` 加无差别 `preventDefault`，
  手指按在图表上就再也滑不动页面。现在 `touch-action: pan-y` 把纵向滚动交还浏览器，
  脚本只在判定为横向手势（位移 >6px 且横向大于纵向）时才接管，且一旦判定为纵向就不再抢事件
- 轻点图表会在该位置显示十字光标，读单根 K 线的开高低收；右轴价格、底部日期同步高亮
- 默认视野 30 根（日/周）、24 根（月），蜡烛实体约 7.5px；右上角 `−` / `+` 可继续缩放（15~240 根）

绘制是手写 canvas，不引图表库。两个实现细节值得记一笔：

1. 均线用**全量**数据算，只把**可见窗口**画出来。否则取最后 60 根再算 MA60，左端会整段缺失。
2. 图表高度用 `clamp(250px, calc(100dvh - 336px), 460px)`，保证主图 + 成交量在小屏也能一屏看完。

### 刷新策略

- 盘中：按设置里的间隔（15/30/60/120 秒）刷新行情与持仓
- **15:00 收盘后：自动补拉一次最终数据**（此时涨停池才是定稿的），成功后标记当天已完成，不再重复请求
- 补拉失败会节流重试，最多 3 次，避免把接口打爆

## 九、构建

```bash
bash build_apk.sh
```

流程：`aapt2 compile → aapt2 link → javac → d8 → aapt add → zipalign → apksigner`，
不依赖 Gradle 和 Android Studio。工具链在 `.toolchain/` 下（JDK 17 + platform-35 + build-tools 35）。

四个踩过的坑，脚本里都已处理：

- aapt2 在**中文路径**下会报 `failed to open directory`，所以整个构建在英文临时目录里做，产物再拷回来
- `-R` 是 overlay 参数，普通资源要作为**位置参数**传给 aapt2 link，否则会报 `does not override an existing resource`

签名用自签名密钥（`keystore/yeren.jks`，口令 `yerenquant`），首次运行自动生成。
分发前建议换成自己的密钥，否则用户无法覆盖安装其他版本的同一个包。

单测覆盖了几个容易写错的地方：当月不完整时的月线堆量、破位大阴不能算买点、翻倍股要剔除、
否决标的排序要靠后、跌停成堆时不能因为分数刚好过线就判成试错期。

- **构建脚本不能吞掉 javac 的退出码**。曾经写成 `javac ... | grep -v xxx || true`，
  结果编译报错却继续用残缺的 class 去打 dex，装到手机上就是直接闪退
  （dex 里只有 R 类，找不到 MainActivity → ClassNotFoundException）。
  现在 javac 失败立即中止，并且出厂校验会断言 dex 里必须能找到壳代码的字符串。

- **`aapt2 link -A` 在 Windows 上会把 assets 条目名写成反斜杠**（`assets/www\js\app.js`）。
  Android 的 AssetManager 只认正斜杠，于是运行时报 `ERR_FILE_NOT_FOUND`，
  而用 zip 工具看中央目录却是"文件都在"。所以组包交给 `tools/pack_apk.py`：
  assets 自己遍历写入、强制正斜杠，并在构建时断言包里没有反斜杠条目、`assets/www/index.html` 可读。
  `aapt add` 同样不可靠，已弃用。

打完包会自动跑 `tools/verify_apk.py`，五项断言全部通过才允许出厂：
条目名无反斜杠 / `index.html` 可读 / assets 与源码逐文件哈希一致 /
`resources.arsc` 未压缩 / `classes.dex` 里包含壳代码字符串。

## 十二、已知限制（诚实说明）

1. **竞价类买点未实现**。文档的「竞价额≈昨日成交额 8%-10%」需要 9:20-9:25 的分笔竞价数据，公开接口拿不到逐笔，所以没有硬做。
2. **断板反包、地天板、空间板破局**需要分时与盘口数据，同样未实现。
3. **波段扫描范围有限**：只扫成交额榜前 100 只里符合条件的（约 60-70 只）。全市场 5000 只逐只拉 380 根日线不现实，也正好避开东财限流。月线堆量本来就是稀缺形态，命中少是正常的。
4. **交易日历是简化的**：只跳过周末，不处理法定节假日。长假前后「昨日涨停池」可能取到空，界面会降级提示。
5. **无回测**。这套模型是规则归纳，没有历史胜率验证，请勿当作策略收益承诺。
6. **持仓数据只在本机**：存在 localStorage，换设备/重装应用不会同步，也没有云备份。盈亏未计算交易手续费与滑点，实际收益会比显示的略低。
7. **装机验证有限**：本环境没有连接 Android 设备，APK 只能做到签名校验 + 包结构校验 + 资源路径断言。已修复一版导致 `ERR_FILE_NOT_FOUND` 的组包问题；若仍有异常，应用内会显示可截图反馈的错误页，而不是系统的"网页无法打开"。
